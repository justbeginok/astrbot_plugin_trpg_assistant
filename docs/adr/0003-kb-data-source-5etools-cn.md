# 知识库数据源选 5etools-cn 结构化 JSON，弃用 DND5e_chm HTM 解析

知识库主数据源为 [5etools 中文站](https://github.com/tjliqy/5etools-mirror-2.github.io)
（cn2.0 分支 `data/` 目录）的结构化 JSON；不解析玩家维护的
[DND5e_chm（5e 不全书）](https://github.com/DND5eChm/DND5e_chm) 的 HTM 页面。
数据构建产物（SQLite）按上游许可 **CC BY-NC-SA 4.0** 分发（NOTICE 署名）。

## 背景

初版设想是把不全书仓库作为内置知识库源。它译文质量高（纯人工校对），但
HTM 是面向人类阅读的排版稿：为法术/职业/怪物各写一套解析器工作量大且脆弱
（上游改版即崩），且 RAG 直接检索排版稿效果差。因此重新选源。

## 覆盖面对比（2026-08 实测）

| 维度 | DND5e_chm（不全书） | 5etools-cn |
|---|---|---|
| 条目覆盖 | 约 30 本精选书（含 2024 核心三本） | 英文 5etools 骨架收录全官方出版物，是超集（模组怪物/新书同步快） |
| 中文译文 | 100% 人工校对 | 已校对条目大部分正是不全书自己的译文——「共库」项目在把 chm 译文搬进 5etools 数据（条目标注 `translator: 不全书`） |
| 独家内容 | DNDBeyond 第三方、自排版速查 | — |
| 结构化程度 | 无 | 法术/职业/怪物/物品/专长/背景均为 JSON，天然支持同名多版本、过滤字段 |

关键事实：法术条目 `name`=中文、`ENG_name`=英文、`source` 区分版本
（PHB=2014、XPHB=2024）、`reprintedAs` 建立同名跨版本引用；
**机翻判定规则与 5etools-cn 网站一致**（js/render.js）：`translator` 缺失或为
「机翻」→ ⚠️机翻，仅「不全书」等人工译者白名单算已校对。

## Considered Options

- **只解析 DND5e_chm HTM**：译文最可靠，但解析器三套起、脆弱、GPL-3.0 数据
  与 MIT 代码混合分发有兼容性负担，否决。
- **混合：JSON 骨架 + chm 文本**：正文质量最高，但两个来源的词条对齐是
  持续维护负担；且实测 chm 译文已通过共库汇入 5etools-cn，混合收益低，否决。
- **5etools-cn JSON 为主（选定）**：超集覆盖 + 结构化 + 机翻标注可甄别。
  不足（部分条目机翻）用 ⚠️ 标注策略兜底；如未来发现某类条目 chm 有而
  5etools-cn 缺，可按混合方案定向解析 chm 补入，schema 的 `source` 字段已预留。

## Consequences

- 覆盖率：936 法术 / 3572 怪物 / 2388 物品 / 276 专长 / 75 背景 /
  30 职业 + 322 子职（构建产物实测，2026-08）。
- 机翻占比约半数（怪物尤多），返回时统一标注 ⚠️机翻，DM 自行甄别。
- 职业-法术关联缺失：中文法术数据不带 `classes` 字段，上游英文数据
  路径不可达（404），本期不提供「某职业能学哪些法术」，README 声明。
- 许可义务：派生库以 CC BY-NC-SA 4.0 发布、非商业、署名（NOTICE +
  `/kb version`）；代码本体与数据许可分离。
- 中文社区译名差异（如 Champion=勇士/冠军）随上游数据走，不做本地别名覆盖。
