# 货币即物品，折铜结算 + 自动找零

v0.20.0 引入商店系统，需要「扣款 / 付款」能力。项目术语一直规定
**货币不是独立概念**（金币等货币就是普通背包条目，不做钱包字段、不做余额校验），
商店结算不能推翻该模型造钱包。本 ADR 把「货币即物品」落地为可结算的口径。

## Considered Options

- **独立钱包字段（推翻术语）**：在角色卡/背包上加金/银/铜数值字段。否决——
  与「货币可 give/put/take 流转」的既有玩法割裂（钱包无法被流转/共享），
  需迁移旧背包数据，且推翻已沉淀的 CONTEXT.md 术语。
- **只认金币、物价取整**：结算只扣「金币」条目，PHB 铜币级物价向上取整。
  否决——物价失真（蜡烛卖 1 金），且与知识库库价（铜币原值）对不上。
- **三币种折铜 + greedy 自动找零（选定）**：约定 金币/银币/铜币 三条目
  为唯一货币，面值 100/10/1 铜币。结算时把玩家三币种折成铜币总额扣减，
  差额自动找零；扣款策略「整币优先、最多破开一枚最小可破大币」，
  玩家原有币种组合尽量保留（不会把一囤金币全换成银币）。
- **价值单位维持无定义**：背包 value 字段无单位 → 商店无法与库价对齐。
  否决；统一为**铜币口径**（整数值），显示层 `format_cp` 换算成
  「X金Y银Z铜」；货币条目的 value 按面值 100/10/1 自动维护，背包总价值
  = 折铜后的全团财富（total_value 对货币条目按面值计、不看存储 value）。

## Consequences

- **结算算法在 money.py 纯函数层**（settle_payment/make_change/parse_money/
  format_cp），无 KV 依赖，单测覆盖边界（1 金买 50 铜 → 破金找 5 银等）。
- **背包侧写入口收敛**：InventoryManager.settle_purchase（扣款+入货）/
  settle_sale（扣货+入款）在同一把 Inventory 锁内原子完成；与 Shop 锁构成
  固定「Shop → Inventory」锁序（见 ADR-0010），无死锁环。
- **迁移成本**：旧手工录入的 value 无单位口径作废，统一按铜币解释
  （如旧 v=2 现显示「2铜」）；部署说明中声明。
- **限制**：只能按三币种结算，不接受其他「货币」（如晶石/便士）——DM
  可自行上架此类物品但无法参与自动结算。
