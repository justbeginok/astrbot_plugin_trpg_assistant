# 背包采用「个人 + 队伍」双模型，KV key 按归属区分

背包功能采用双模型：个人背包（`inventory:{会话来源}:{发送者ID}`）与队伍背包
（`inventory:party:{会话来源}`）各自独立存储于 AstrBot KV；物品流转
（put/take/give）在管理器单把锁内完成源扣除与目标合并的原子写入。
货币不作为独立钱包字段，而是普通物品条目。

## Considered Options

- **单一共享背包**：实现最简单，但无法表达「这是我的药水」的所有权，
  跑团中个人物资与公共物资混为一谈，否决。
- **独立钱包字段（gp/sp/cp 多级货币）**：更贴近 D&D 规则书，但引入
  货币换算、余额校验、找零等一系列专属逻辑，且不同团规货币体系不同；
  「金币即物品」用零额外机制覆盖了记帐需求，否决。

## Consequences

- KV key 布局一旦发布即产生持久化用户数据，后续若调整 key 结构或
  物品 schema，需要提供迁移逻辑。
- 未来角色卡（/char）落地时，个人背包可整体挂载到角色卡 key 下，
  队伍背包保持会话级不变。
- LLM 工具 `manage_inventory` 不暴露 give（无法 @ 目标）与队伍背包
  clear（破坏性操作保留给命令层 + 权限检查）。
