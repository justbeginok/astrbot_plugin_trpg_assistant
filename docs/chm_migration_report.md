### 复盘：法术解析的实际难点（均已解决）
1. 2014/2024 元数据格式差异（空格数字/仪式标记/职业全名 vs 简写）；

## 4. 逐类评估

### 4.1 状态（S，0.5-1 天）
- **md**：`玩家手册/状态.md`（`### 目盲Blinded` 三级标题）、`玩家手册2024/术语汇编/状态.md` 等。
- **格式**：条目简单（标题+描述段），天然结构化，无元数据块。
- **现状**：5etools-cn 35 条，正文机翻风险低（状态短）。
- **建议**：收益最低但成本也最低——若做可顺手换掉机翻文本，纯 win。

### 4.2 物品（M，3-5 天）
- **md**：`速查/5E万器大全.md` 速查表（887 行 ≈443 条魔法物品，14 列：
  物品名/稀有度/类别/子类别/同调/同调条件/来源，**与法术速查表同构**）+
  各书 `魔法物品.md` 详述文件；另有合作方万器大全（第三方）。
- **格式**：速查表结构化优（复用 `parse_quick_table` 改列即可）；详述散落
  各书、命名不一（魔法物品.md/新装备.md/宝藏.md…），同法术的散落定位工作。
- **现状**：2035 条（含基础物品 200+ 与魔法变体 214，v0.41.0 变体已独立建模）。
  ⚠️ 万器大全只有魔法物品，**基础物品/变体在 md 的覆盖需单独评估**；变体
  （焰舌/霜铭）当前走 items-base + magicvariants.json 的 5etools 模型，
  md 替换会破坏该模型——**建议物品只替换详述正文、保留 5etools 结构化壳**。
- **风险**：物品详述与速查表名对账（同名多版本/多稀有度「多种稀有度」）；
  现有 kb_patches/items.json（89 条警戒武器补丁）与新源的关系。

### 4.3 专长（M，2-3 天）
- **md**：各书专长文件（玩家手册2024/专长/ 按 通用/起源/战斗风格/传奇恩惠
  分文件；塔莎/斯翠海文/万象无常书等散落），**无统一速查表**，标题层级
  各文件不一（`####`/`###`/`**名**` 混用）。
- **现状**：276 条，AI 概要（feat_enrich）与能力标签（feat_keyword）已齐。
- **难点**：条目切块规则需按文件适配；前置条件（先决条件）与属性提升的
  结构化提取（现有 `feat_ability`/`feat_type` 侧表字段依赖 5etools 结构化）。

### 4.4 种族 / 背景（M，各 2-3 天）
- **md**：各书种族/背景文件，部分散落（异界传送 Plane Shift 系列按种族拆分
  文件）。条目格式以 `####`/`###` 标题为主，种族特性列表/属性加值在正文
  自然语言中（现有库的 speed/darkvision 数值列需从文本提取或 5etools join）。
- **现状**：种族 160/背景 148 条，概要标签已齐。
- **难点**：种族数值字段（速度/黑暗视觉）是侧表结构化列，md 纯文本提取
  需正则（`速度30尺`/`黑暗视觉60尺`），比法术的 range 解析复杂但可控。

### 4.5 职业 / 子职 / 特性（L，5-8 天）
- **md**：每职业一目录多文件，章节式结构（`### 成为一名吟游诗人…`、
  `### 职业特性…`），**非条目式**——特性以表格/列表散布在章节中，无
  `#### 特性名｜English` 统一锚点。
- **现状**：30 职业/322 子职/2118 特性（class_features 表），AI 概要+定位
  标签已齐；`/查职业 X 特性 Y` 依赖结构化特性行。
- **难点**：特性切块（表格式特性描述、多职业共用特性表）、子职变体命名
  （显示名≠短名）、特性等级/来源字段（现有 class_features 有 level/source
  列）全要从章节文本反推——**解析器开发成本高且对账难**。
- **建议**：职业/子职/特性保留 5etools JSON（结构已好、中文覆盖尚可），
  md 只做机翻条目的正文替换（补丁通道），不整类重建。

### 4.6 怪物（XL，10-15 天）——最大挑战
- **md**：每怪一文件（`怪物图鉴/不死生物/僵尸.md`），图鉴 2014 版 344 文件 +
  2025 版 600 文件 + 多元宇宙的怪物 316 文件 + 各扩展书生物目录 2300+ 文件，
  覆盖面远超 5etools-cn（3741 条）。
- **格式**（僵尸实测）：
  ```
  丧尸Zombies
  *中型亡灵，中立邪恶*          ← 体型/类型/阵营
  护甲等级：8
  生命值：22（3d8+9），
  速度20尺
  力量13（+1） 敏捷6（-2） 体质16（+3）   ← 一行 3 个属性
  智力3（-4） 感知6（-2） 魅力5（-3）
  豁免：感知+0
  伤害免疫：毒素
  ...
  挑战等级：1/4（50 XP）
  *不死坚韧Undead Fortitude。*…  ← 特性（斜体名+描述）
  动作
  *猛击Slam。…*                   ← 动作
  食人魔丧尸Ogre Zombie           ← 同文件多变体！
  ```
- **现状**：3741 条，**机翻约半数**（怪物是知识库最大的机翻重灾区，CHANGELOG
  曾记 1286 条机翻）——md 人工翻译 lore + stat block 的替换价值最高。
- **难点**：
  1. **stat block 纯文本解析**：AC/HP/速度/属性/豁免/免疫/感官/语言/CR 都是
     「中文键：值」行（可正则），但属性六行**一行三个**连排、特性/动作/传奇
     动作/反应分区、同文件多变体（按 `名English` 头再切）、2024 版 stat
     block 格式差异（如 护甲等级 可能带「（自然护甲）」）；
  2. **结构化字段**：现有 monsters 侧表（cr/mtype/size）+ entry_tags
     （dmg_resist/dmg_immune/condition_immune/environment/creature_type…）
     全依赖结构化解析，md 文本提取需完整重写提取器（`_monster_tags`）；
  3. **体积**：3741 条 × 解析+对账+抽检，是全库最大的单点工程。
- **建议**：怪物重建收益最大（机翻重灾区）但风险也最大——若做，先以
  2024 版图鉴 600 文件试点（版本新、覆盖 2025 规则），2014 图鉴/多元宇宙/
  扩展书分阶段；**每阶段以与 5etools-cn 的 CR/类型/免疫对账为质量门禁**。

## 5. 方法论沉淀（法术样板已验证）

1. **速查表优先**：有速查表的种类（法术/物品）先解析速查表得结构化元数据，
   再以「名+来源」join 详述正文——解析成本最低、对账最易。
2. **锚点对账**：以速查表/现有库为锚反查全部 `####` 标题，自动定位散落文件，
   未命中清单人工裁决（`audit_chm.py` 模式）。
3. **规则富化 + 兜底词**：缺口富化先用规则生成（summary 首句 + 关键词提取 +
   学派/类别兜底），保证覆盖率 100%，再逐批 AI 精修质量差的。
4. **质量门禁**：条目数对账（±0）、字段非空率、与 5etools 结构化字段抽样
   对比（法术抽 20 条零异常）；测试全量 1167 passed。
5. **混合源策略**：md 主源替换「中文正文/详述」高价值层；5etools JSON 保留
   「结构化壳」（职业法术表/物品变体/数值侧表）——ADR-0018 已验证该分界。

## 6. 风险与开放问题

- **怪物 stat block 多版本格式差异**（2014/2024/多元宇宙）是最大不确定性，
  建议试点阶段先量化差异矩阵再定解析器。
- **物品基础物品/变体在 md 的覆盖**未确认（万器大全仅魔法物品），替换范围
  需先审计。
- **专长/职业标题层级不统一**，切块规则需按文件适配（无速查表锚点）。
- **机翻判定**：md 为主源后 is_machine 恒 0，原「⚠️机翻」标注体系对
  md 源失效（法术已处理；怪物若重建需重新定义质量标注）。
- **上游同步**：5etools-cn 定期 fetch 的增量更新机制对 md 源不适用——
  5e_chm 的更新依赖 git pull + 重跑 htm_to_md + 重跑解析（一键脚本可封装）。
