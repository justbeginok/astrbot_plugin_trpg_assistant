# 商店：单店单 KV + DM 配置 + 买卖原子事务

v0.20.0 商店系统的数据模型与事务边界设计。商店是「DM 配置的商品列表 +
玩家自助买卖结算」的会话级功能。

## Considered Options

- **多店/命名商店（铁匠铺/杂货铺）**：会话内可建多家店、先选店再买。
  否决——需要显式维护店名索引（同角色卡 index），命令多一层选择，
  KV 与交互复杂度明显上升；跑团场景「一家店」通常够用，DM 可随时
  上下架改货实现「换店」。
- **无库存概念**：所有商品无限供应。否决——DM 想卖「只有一瓶的治疗
  药水」就做不到。最终选择：**可选库存**（stock=None 无限，0=售罄，
  >0 计数），买入扣减、卖回增加，无限库存买卖均不变化。
- **回购收任何物品 / 回购即销毁**：前者商店列表会被战利品冲乱；
  后者 DM 无法从商店买回玩家卖出的好东西。最终选择：**只收在架商品**
  （按「商店售价 × 回购系数」计价），不上架新条目；回购系数默认 1.0
  全价，DM 可配（clamp 0–2）。
- **价格来源**：默认知识库库价（PHB 定价，铜币），DM 可按商品覆盖
  （设价「自动」恢复库价）。价格覆盖优先，无覆盖无库价 → 不可交易
  （提示 DM 设价），杜绝凭空定价。
- **KV 布局**：`shop:{origin}` 单 key 存整店（有序列表 + 回购系数），
  与背包 `inventory:{origin}:{sender}` 并列，无额外索引需维护。

## 锁序与原子性（跨管理器事务）

买卖同时写商店与玩家背包两把管理器锁。固定锁序：
**先 Shop 锁，后 Inventory 锁**；背包侧每次写入收敛为
InventoryManager 的 settle_purchase / settle_sale 单次调用（同一把
Inventory 锁内「扣货币+入货 / 扣货+入货币」原子完成），Shop 锁内先校验
（在架/有价/库存/货币足）后写，任一失败不产生写入。Inventory 永不反向
持 Shop 锁，锁序无环即无死锁。副作用：背包在 Shop 锁内被读写，
`/bag` 等背包命令与商店买卖串行化，QPS 可接受（跑团群场景）。

## Consequences

- **一条命令初始化**：`/商店 初始化` 从知识库取 source∈{PHB,XPHB} 且
  rarity=none（非魔法）的有价物品全量上架（同名去重取 2024/XPHB 价），
  天然排除魔法物品（DMG 等来源）；重建保留回购系数，覆盖商品列表。
- **购买自动带库重/库价**：成交入包的物品条目自动写 weight_lb（库重）
  与 value（成交单价，铜币），实现「物品库同步到背包」。
- **权限**：上架/下架/设价/设库存/初始化/回购率走
  `_check_destructive_permission`（群聊白名单或管理员、私聊放行）；
  买卖与查看全员开放。llm_tool `manage_shop` 只开放 list/buy/sell，
  管理操作不暴露给 LLM。
- **限制**：买卖仅针对个人背包（队伍背包不参与结算）；无交易税；
  不支持「买 N 送 M」类定价规则（可经 DM 设价模拟）。
