# 纯文本输出约定（去 Markdown，保纯文本排版）

v0.42.0 确立跨模块的展示约定：插件所有用户可见输出以「纯文本」为准，
去掉 QQ/onebot 等聊天平台不解析的 Markdown 格式控制符号，但保留
`- ` 列表、`1. ` 编号、分隔线、emoji 等即使不解析也保持可读性的纯文本
排版。formatter.py（骰子模块）自始即遵守「不使用任何 Markdown 语法」，
本 ADR 将其推广为全局约定并说明判定规则。

## Considered Options

- **保留现状**（背包/商店/角色卡等用 `**名称**` 加粗）：改动小，但
  QQ 上 `**` 原样显示，产生视觉噪音；且与 formatter.py 既有约定矛盾。
- **运行时统一 strip**（所有输出过一遍 `re.sub(r"\*\*", ...)`）：无法
  安全实现——骰式表达式内含语义符号（`3d6>3`、`d20+5#攻击检定`、
  formatter 成功计数的单 `*`），正则清洗会误伤。
- **手工清理字面量 + 测试守卫**（采纳）：逐个修改输出字符串，去掉成对
  `**`/`*`/`~~`、行首反引号/`>`/`#`；保留 `- ` 列表、`1. ` 编号、
  `——…——` 分隔装饰、emoji、`×`/`→`/`（…）`/`：`/`=`、骰式表达式、
  不成对单 `*`。新增 `test_no_markdown_output.py` 参数化守卫，
  驱动代表性命令/工具/format 输出断言无 `**`/`~~`、行首无 `>`/`#`，
  防止回潮。
- **解析兼容**：card_import 的卡名头正则原本只认 `**名字**（版本）`，
  去 markdown 后 format_sheet 输出「📜 名字（版本）」无法 round-trip
  再导入 → 正则放宽为「带 `**`（兼容旧文本）或带 `📜` 前缀的纯文本头」，
  宽松键行（`名字：A`）不受影响。

## Consequences

- **清理范围**：inventory.py `format_item_line`、shop.py `format_shop`、
  character.py 卡名行、chargen.py 代骰/起始金币文案、initiative.py
  先攻文案、card_import.py 报错示例、main.py 全部命令文案与 LLM 工具
  返回值（约 30 处）。
- **docstring/注释中的 `**` 不动**（非用户可见输出）；dict 解包
  `{**fields}` 属语法不动。
- **测试同步**：约 70 处断言去掉 `**`；test_card_import.py 中带 `**`
  的文本保持原样（仍是合法的解析输入，覆盖向后兼容）。
- **判断标准一句话**：输出里不应出现「用户看不懂为什么存在的符号」；
  `- ` 和 `1. ` 在纯文本里读起来仍是列表/编号，保留。
