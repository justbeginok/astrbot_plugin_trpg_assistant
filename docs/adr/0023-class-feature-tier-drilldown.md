# ADR-0023：职业特性分层钻取与概要总表（/查职业 排版改造）

- **状态**：已采纳
- **日期**：2026-08-13
- **版本**：v0.48.0

## 背景

`/查职业` 是 QQ 群跑团场景的高频查询。原输出形态：

- 默认总表：`1级：回气；1级：战斗风格；…` 全挤一行「；」串联，等级反复出现、
  无视觉分组，扫读困难；
- `特性` 全量模式：一次把职业全部特性正文塞进**单条** 4000-9000+ 字符的消息
  （奇械师 8182、德鲁伊 6329），在 QQ 群对话框里是纯灾难；
- 2014/2024 双版本全文各发一遍，内容重复率近 100%，长度再翻倍。

数据侧发现：`class_features.summary`（一句话概要）构建期全覆盖（677/677，
单条 ≤101 字符），每职业全部概要合计仅 1500-2400 字符——天然适合做中粒度层。

平台侧核实：AstrBot pipeline 对 async generator 命令 handler **每个 yield 发一条
独立消息**（`core/pipeline/context_utils.py`），「一次查询分条连发」零平台改动。

## 决策

1. **分层钻取 + 按需分条，无状态**：不引入 KV 翻页状态（群聊里多人/消息交叉、
   超时清理都是状态机的坑）。三档展示：
   - **L1 概要层**（默认）：按层级段分组（第1层 1-4级 / 第2层 5-10级 /
     第3层 11-16级 / 第4层 17-20级），每特性一行「N级 名称：一句话概要」；
   - **L2 钻取**：子职名 / 版本 / `第N层` / `N级` / `N-M级` → 命中特性全文；
   - **L3 全量**：`特性` 关键词 → 按层级段切成多条消息连发，每条一个层级段、
     带【职业·第N层 X-Y级】标题（单特性 `特性 名` 保持 v0.29.0 跨版本语义单条）。
2. **版本策略 = 群规则感知**：默认版本取群级开卡规则
   （`chargen_rule:{origin}` 的 edition，新增 `ChargenManager.get_rule_edition`，
   无 KV 数据返回 None 以区分「显式设 2014」与「未设规则」）→ 私聊/无规则取
   最新版（`editions[0]`，edition DESC）；显式第二参数 2014/2024 覆盖。
   目标版本无数据自动回退另一版本并提示（回退判断只看本职特性 base_rows——
   子职候选查询不带 edition 过滤，不能作为版本有无依据）。
3. **版本过滤下沉到查询层**：`class_features(edition=)` 过滤 base/sub 行；
   单特性细化（feature=特性名）不过滤（跨版本），feature 为 `"*"`/未传时过滤。
   命令层总是单版本数据 → 概要层/全文层自然不重复。
4. **LLM 工具默认概要层**：`query_dnd_knowledge` class_features 不传
   feature/subclass 时返回分层概要总表（token 友好），docstring 指引
   `feature="*"`/特性名/`class_level=N` 拿全文；40 参数 schema 不变。
5. **子职一次给齐不变**（v0.11.0）：子职特性 4-5 条、约 1.5k 字符，保持全量，
   仅应用版本策略与头部统一（【职业·子职 显示名】）。
6. **残留标签双修复**：`kb_tags._TAG_RE` 标签名放开数字
   （`{@5etools 专长|feats.html}` → 专长，根因修复，重建库后构建期自动干净）；
   kb.py 显示层渲染前兜底 `clean_5etools_tags`（幂等，清洗已发布旧库残留）。

## 结果

- `/查职业 战士`：分层概要总表（第1~4层 × 「N级 名称：概要」），单条 ~1500 字符。
- `/查职业 战士 特性`：head + 每层一条全文 + 提示，共 6 条（单版本 4 层），
  每条 400-800 字符。
- `/查职业 战士 5级` / `第2层` / `2024`：确定性钻取，无状态。
- 群规则 2024 的群：默认看 2024 版；私聊默认看最新版。

## 后果

- `ClassFeatureRow` 增 `edition` property；`class_features()` 增 `edition` 参数
  （默认 None 行为不变，旧调用零回归）。
- 新增 `CLASS_TIERS`/`tier_of`、`ClassTierSegment`/`ClassDisplay`、
  `build_class_display`/`class_display_messages`/`_render_overview_segment`/
  `_render_full_segment`（kb.py 静态方法簇，遵循「Manager + format_*」惯例）。
- `/查职业` 第二参数语法从 `[子职|特性]` 扩展为
  `[子职名|版本|层级|等级段|特性]`，帮助文本与 README 同步。
- 概要层多版本兜底只取最新版（LLM 工具路径未传 edition 时），其余版本仅提示。
- 全文分条数量上限 = 4 层 + head + 提示 ≈ 6 条/次，属可接受的群聊刷屏量。
