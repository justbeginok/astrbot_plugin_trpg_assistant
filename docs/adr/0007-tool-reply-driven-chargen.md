# 车卡引导采用「工具返回驱动」的插件状态机（混合式）

车卡引导（v0.17.0）的形态是混合式：**插件维护引导状态机（草稿 KV），
LLM 通过 `guide_chargen` llm_tool 读写推进**。每次工具调用返回三段式
文本——【进度】步骤 x/n + 路径、【校验】本步接受/硬拒绝原因、【下一问】
LLM 接下来要问玩家的唯一一个问题。LLM 只做话术包装，一次只问一个问题，
禁止替玩家作答、禁止跳步。

状态真相在插件草稿 KV（`character:draft:{origin}:{sender}`），
跨 AstrBot 重启可续传；完成落库后删除草稿，重开覆盖。

## Considered Options

- **纯 prompt 引导（LLM 自由对话，工具只管存数据）**：LLM 自由度最大、
  实现最省，但长对话后 LLM 会忘步骤/忘群规则，状态真源分裂（LLM 记忆
  vs 插件草稿），「状态机」名存实亡；LLM 上下文一旦被清理，引导无法
  续传，否决。
- **插件状态机主导（命令向导，LLM 不参与）**：最确定可测试，但对话
  僵硬，玩家要记命令，违背「让 LLM 根据规则逐步引导」的核心诉求，否决。
- **命令驱动推进（/车卡 下一步）**：玩家体验差，且 LLM 在场时绕开
  LLM，否决。

## Consequences

- 引导流程（2014：种族→职业→背景；2024：职业→起源→属性）与校验器
  全部在插件内确定性执行——购点花费由插件计算，**LLM 不自行算数**，
  杜绝算错。
- 命令层提供无 LLM 兜底入口：`/车卡 答 <答案>` 走同一状态机，输出
  同一三段式文本（其中【下一问】对纯人类路径稍显「给 LLM 的指令味」，
  属可接受折衷）。
- LLM 遵从度仍是软肋（可能跳过 answer 直接编卡）：工具返回内置
  「禁止替玩家作答」指令 + 校验硬拒绝兜底，双重防线。
- 状态机的每步校验、路径分支、DONE 落库均可用 FakeEvent 全链路测试，
  不依赖真实 LLM。
