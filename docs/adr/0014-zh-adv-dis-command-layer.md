# 中文「优势/劣势」走命令层预处理而非 parser 语法

v0.38.0 起支持 `/r d20优势`、`/r d20劣势` 及组合（`d20优势+2`、`d20优势+1d4`）
等中文紧贴后缀写法，等价于既有英文 `adv`/`dis` 语法糖（掷 2 枚骰取大/取小）。
实现位置在 **main.py `_do_roll` 命令层**（`_map_zh_adv_dis` 正则映射），
**不修改 dice_parser 上游**。

## 背景

- `dice_parser.py` 是上游（Dracowyn/astrbot_plugin_dnd_dice）核心，标记为
  「只读扩展」（ARCHITECTURE §5.1）：fork 后默认不轻易改 parser 语法，
  扩展优先放在 main.py 命令层。
- 引擎已有完整 adv/dis：`d20adv`=2d20kh1、`d20dis`=2d20kl1（骰数>2 报错，
  不限骰面）。缺口只是 parser 不认中文——`_strip_label` 在首个 CJK 字符处
  把后续截断为标签，`d20优势` 若不预处理会被静默解析成「普通 d20 + 标签」。

## 决策

- **命令层映射**：`_do_roll` 开头（parse 之前）调用 `_map_zh_adv_dis`，
  正则 `([0-9A-Za-z])优势` / `([0-9A-Za-z])劣势` 仅把**紧贴 ASCII 骰式字符**
  后缀的「优势/劣势」替换为 adv/dis。三个掷骰入口（`/r`、自定义前缀路由、
  `roll_dice` LLM 工具）都经 `_do_roll`，一处改动全部生效。
- **非紧贴写法一律报错**（孤立词检测 `_ZH_ORPHAN_ADV_DIS`）：带空格
  （`d20 优势`）、前置（`优势d20`）、单独使用（`优势`）返回
  「优势/劣势必须紧贴骰子」解析错误。理由：带空格静默当普通 d20 会让
  用户「以为是优势实际没加」——比报错更危险。
- 标签内「优势」二字（如 `d20 战斗优势`，前置为 CJK/空格外的字）不匹配
  正则、不误伤，维持既有标签语义。

## Considered Options

- **全局 `replace("优势","adv")`**：实现最简，但会把标签里/句中的「优势」
  一并改写（`d20 战斗优势` → 标签变「战斗adv」），误伤面不可控，否决。
- **在 dice_parser 加中文分支**：语义上最彻底，但违反「上游只读」约束，
  需同步上游、维护 fork 差异，且 `_strip_label` 的 CJK 截断逻辑复杂易错，否决。
- **`d20 优势`（空格）静默当标签**：与既有标签语法一致、零新增逻辑，但
  造成「用户以为掷了优势、实际是普通 d20」的静默失误，与「其他写法报错」
  的产品语义冲突，否决（用户确认）。

## Consequences

- 中文语法是**纯命令层糖**：`/r`、自定义前缀、LLM 工具三入口自动生效；
  车卡规则自定义骰式（`/车卡规则` 的 roll 表达式）不经过 `_do_roll`，
  不含「优势/劣势」映射——记为边界，规则表达式仍用 adv/dis。
- 命名掷骰同名覆盖：玩家登记 `d20优势` 为命名掷骰（`/卡 骰 d20优势 …`）
  时，角色卡联动优先于本语法（与既有「named_rolls 优先于内建别名」一致）。
- 历史记录保留用户原始输入（`/rh` 显示 `d20优势` 而非 `d20adv`）。
- 超边缘不兼容：全角骰面（`d２０优势`）正则不命中，按标签解析——极罕见，
  不做兼容。
- `4d6kh3优势` 等显式骰数>2 的写法命中引擎守卫报「固定 2 颗骰子」（文案
  提及英文 adv/dis），暂不自定义中文文案。
